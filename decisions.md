Format: ID · decision · rationale · evidence · status. "Sim-driven" = changed because an offline simulation
in `phase0-probes/sim` failed; the failing run is described so the change is auditable.

## Transactions

| ID | Decision | Rationale / evidence | Status |
|---|---|---|---|
| D-TX-1 | Protocol: in ONE game tick: synchronous durable `PREPARE` (txn row + reservation + expected wallet before/after + play-time) → re-read wallet, verify == `cash_before` → apply ALL money-coupled game-side effects → synchronous durable `COMMIT` (commit row + projection). A rolled-forward commit is stamped with `p_prepare` (its effects existed from that tick). World actions that cannot complete in one tick (handover scenes, spawns) are separate bounded steps before (precondition) or after (delivery) the atomic core. | E1-8 / A-SL-4: a save snapshot cannot interleave inside one tick. **Sim-driven** stamp fix (rolled-forward commit stamped with recovery play-time excluded it from an earlier save). Cost: 2 fsync'd commits per transaction tick (budget in LSAX-PERFORMANCE-BUDGET.md, measured by P-DB-01). | DESIGN DECISION (sim-verified) |
| D-TX-2 | **WITHDRAWN in DRAFT2 (Correction Pass 1) — superseded by D-TX-4; kept as history, not normative.** Recovery of a PREPARED txn is decided only by evidence: same anchor position AND play-time ≥ p_prepare AND wallet == `cash_after` (≠ `cash_before`) → roll forward; wallet == `cash_before` or different position → abort; anything else → RECONCILE_REQUIRED. Money-neutral transactions need another verifiable discriminator or they resolve to RECONCILE_REQUIRED. | Never guess. | DESIGN DECISION (sim-verified) |
| D-TX-3 | Idempotency scope = the active timeline path. A key orphaned by a rewind may be committed again (e.g. the same offer accepted again after loading an earlier save). | The orphaned commit's effects do not exist in the loaded world. | DESIGN DECISION |

## Correction Pass 1 (DRAFT2) — decisions (baseline f6aff47; audit CORRECTION_REQUIRED)

Principle for every recovery/lineage rule: **no positive evidence → no automatic acceptance**. Accepted evidence
types are only (a) LSAX's own durable knowledge of its own actions, (b) runtime-scoped proof that the game session
did not change, (c) byte-identical content of a save LSAX itself observed being written. Wallet values, play-time,
wall-clock proximity, time windows and slot names are **correlations** and are never accepted as lineage or as
proof that a transaction was applied.

| ID | Decision | Finding | Status |
|---|---|---|---|
| D-SL-13 | **Save lineage = content identity.** A save file is TRUSTED only if its SHA-256 equals the hash of a save LSAX observed being written while running and anchored, corroborated by a game save-event signal (A-SL-12), or equals any previously trusted content (byte-identical restore). Every other file — changed while LSAX was down, present before install, copied while running without a save event, or with ambiguous event correlation — is UNTRUSTED and never a lineage source. | P0-03 | DESIGN DECISION (sim-verified); runtime A-SL-12 → B-01 |
| D-SL-14 | **Continuation requires a session token**: at each successful anchoring LSAX writes a fresh random 31-bit token as a decorator on the player ped and persists it. A restart that reads the same token on the player ped proves the same live game session (no load, no new process) → continuation. P/W equality no longer admits continuation. Without the token (character switched while LSAX was down, decorators unavailable) → slot path. | P0-03 (self-found continuation hole) | DESIGN DECISION (sim-verified); runtime A-SL-10 (PC-7) → B-01 |
| D-SL-15 | **Anchoring without a session token = hypothesis exclusion.** LSAX enumerates every explanation of where the current world came from: `FILE(slot)` for every present slot file, `LIVE` (the world LSAX last ran in, reached without a load — only in the same process and only if play-time ≥ LSAX's own last live observation), `NEW_GAME` (play-time ≤ NEWGAME_P_MAX). A fingerprint mismatch (play-time outside the file's recorded poll bracket, or a recorded wallet vector ≠ current) **excludes** a hypothesis; a match never includes one. UNTRUSTED files cannot be excluded (content unknown). Accept only if every non-excluded hypothesis has a known LSAX state, they all agree, and at least one is a content-identified file; otherwise RECONCILE_REQUIRED(UNTRUSTED_PRESENT / PENDING_UNKNOWN / AMBIGUOUS / NO_MATCH / SESSION_UNPROVEN). No STANDARD/STRICT policy split: the earlier STANDARD policy (accept despite unexcludable UNTRUSTED files) is withdrawn as correlation-based. | P0-03 | DESIGN DECISION (sim + regression verified) |
| D-SL-16 | **Residual hypotheses made explicit.** (i) `LIVE` state = active head if the pending transaction is NOT_STARTED, head+txn if APPLIED, unknown if APPLYING; (ii) a script-domain start that fails writes a durable `MISSED_START(process)` marker; a later token-less start in the same process → RECONCILE(MISSED_START); (iii) pre-install files are `PRE_INSTALL`: LSAX state EMPTY (known — this journal has no effects in them), fingerprint unknown (never excludable); (iv) a new game has LSAX state EMPTY. Cost: loads while pre-install files exist, forward cross-branch loads in the same process, and new games need an explicit player choice (R-SL-3). | P0-03 | DESIGN DECISION (sim + regression verified) |
| D-SL-17 | **Poll bracket instead of a latency window.** An OBSERVED ledger row records the play-time bracket `[p_lo, P at the observing poll]` where `p_lo` = P at the last poll **before the save-event signal was first seen** (if no signal was seen while running: the previous poll) — the snapshot happened after it (A-SL-6 monotonic, A-SL-12). Wallets are recorded only if unchanged across the same bracket (LSAX's own writes restart it; A-SL-14); otherwise unknown (NULL). Two game saves inside one event-correlation window are both UNTRUSTED. Replaces the fixed `LAT_MS` window of DRAFT1. *Amended during C0-15 (self-found SF-5): with asynchronous file writes a bracket starting at the poll before the file change could exclude the true file (sim reproduced I0 failures).* | P0-03 (+ SF-5) | DESIGN DECISION (sim + regression verified) |
| D-SL-18 | **Save-in-progress gate.** No transaction (PREPARE) starts while the game's save-event signal is active; the intent is deferred to a later tick, never dropped. Guarantees that the LSAX head cannot change between a save snapshot and the observation of its file, so the ledger row's `head_txn` is the snapshot's head even when the file is written asynchronously. *Self-found SF-4 during C0-15; without the gate the model reproduces wrong-head attribution (31 I0 violations in 30 adversarial episodes; regression P0-03/24b, /26).* | P0-03 (+ SF-4) | DESIGN DECISION (sim + regression verified) |
| D-TX-4 | **PREPARED recovery uses only LSAX's own evidence.** PREPARE durably sets `apply_status=APPLYING`; the in-memory status (NOT_STARTED → APPLYING → APPLIED) is flushed in `Aborted`. Continuation + APPLIED → ROLL FORWARD (stamped p_prepare); continuation + NOT_STARTED → ABORT; continuation + APPLYING or no flush → RECONCILE(PENDING_UNKNOWN); slot-anchored → ABORT (D-TX-5 guarantees every TRUSTED save predates the pending apply); no anchor → RECONCILE. Wallet equality is never evidence. | P0-02 | DESIGN DECISION (sim-verified) |
| D-TX-5 | **Apply/COMMIT fault handling:** if COMMIT fails after the game-side apply, LSAX compensates in the same tick (restore wallet, verify) and durably ABORTs; if compensation fails, LSAX enters FAULT: it stops observing saves and refuses all operations until restart. Hence no TRUSTED save can ever post-date an unrecorded apply. | P0-02 | DESIGN DECISION |
| D-TIME-2 | **PT is an anchor coordinate only.** MT is never reconstructed from PT. The MT state `(mt, base_mt, recent_credits)` (rolling-cap bookkeeping included) is restored exactly from LSAX's own records: `Aborted` flush (continuation, clean), last durable checkpoint (continuation, unclean; ≤ 30 MT min base loss, never a credit), the save-ledger row sampled after skip detection (slot anchoring), campaign root (EMPTY). Skip credits are durable at grant (immediate SYS_MT_CHECKPOINT). MT does not advance while LSAX is not running. | P1-03 | DESIGN DECISION (regression verified 21/21) |
| D-ID-6 | **Handle, decorator and binding cache are scheduling hints only.** Every observation of a world vehicle reads the full fingerprint and re-runs the §4.4 decision over the lossless candidate set; Bound stays Bound only if that decision BINDs the same record. | D-ID-8 | **Explicit confirmation limits.** AMBIGUOUS → Bound by player confirmation only if exactly one record scores ≥ 60 for the entity and either the plate text+style equal (colour/mod differences only) or the player occupied the entity continuously since the last BIND of that handle to the record (in-place mod-shop change). Truncation never yields uniqueness or NO MATCH. | P1-02 | DESIGN DECISION (proof + sim) |
| D-JRN-1 | **System transactions.** Every journaled change, including periodic ones, is a transaction: kinds `SYS_MT_CHECKPOINT`, `SYS_ODO_CHECKPOINT`, `SYS_MARKET_STEP`, `SYS_HEAT_DECAY`, `SYS_HEAT_EVENT`, `SYS_LISTING_EXPIRY`.
