# LSAX Phase 0 — decisions.md (durable decision log)

Format: ID · decision · rationale · evidence · status. "Sim-driven" = changed because an offline simulation
in `phase0-probes/sim` failed; the failing run is described so the change is auditable.

## Save/load & persistence

| ID | Decision | Rationale / evidence | Status |
|---|---|---|---|
| D-SL-1 | Candidate persistence model = **D "Anchored Timeline"**: LSAX DB independent of GTA save files (C) + append-only commit journal organised as a tree of timelines (B-like rewind by branching), anchored to GTA saves by a passive fingerprint (play-time stat + per-protagonist cash) and a per-slot save ledger. | Only model compatible with E4-4 (no save id natives). A rejected (no slot id); B alone and C alone insufficient (LSAX-SAVELOAD-FEASIBILITY.md §3). | DESIGN DECISION, feasibility **BLOCKED by B-01** (runtime assumptions A-SL-1/5/6/7) |
| D-SL-2 | Anchoring is performed at **every** LSAX session start (constructor after SHVDN domain load) and on any in-session discontinuity; "play-time increased" is NOT evidence of continuity. | **Sim-driven.** First `journal_timeline_ref.py` run: 16 901 invariant failures. Trace (ep0, G=1ms): slot 1 saved on branch 2 at P=3956; player loaded slot 0 (P=2795), then slot 1 again (P=3956 > last_p 2795) → the draft rule "rewind only if P < last_p" treated it as continuation and dropped txn 12 that exists in the loaded world. | DESIGN DECISION (sim-verified after rewrite) |
| D-SL-3 | **Save-slot ledger**: LSAX keeps, per GTA save file, only the observation of its CURRENT content (mtime/size/SHA-256 → timeline, play-time at detection, cash vector). Overwritten saves can never be loaded, so their observations are irrelevant. | Reduces anchor candidates to ≤ number of slot files (~16) instead of all history. | DESIGN DECISION |
| D-SL-4 | Saves written while LSAX was not running are attributed to the timeline active when LSAX stopped, with play-time window `[last_p, last_p + wall_downtime + slack]` (play time cannot advance faster than wall time). If a transaction was PREPARED but unresolved at that moment, such observations are marked `pending_txn` and matching them yields RECONCILE_REQUIRED. | Bounded attribution without guessing. Foreign/copied save files outside the window never match → safe refusal. | DESIGN DECISION |
| D-SL-5 | **Always fork** a new timeline at each anchoring (cheap row). Guarantees play-time is monotonic along every timeline path, which the anchor lookup relies on. | Prevents overlapping play-time within one timeline after loading an earlier save that is newer than the last persisted heartbeat. | DESIGN DECISION |
| D-SL-6 | Zero or ≥2 distinct candidate states → **RECONCILE_REQUIRED**: market/transaction operations refused, projection untouched, debug inspector shows candidates; resolution is an explicit player action (choose candidate or start new campaign). Never auto-merge. | Mandatory invariant 4 applied to timelines. | DESIGN DECISION |
| D-SL-7 | LSAX never reads game state inside `Script.Aborted` and never relies on `Aborted` for durability. All durability comes from synchronous SQLite commits at protocol points. `Aborted` only flushes values sampled in the last completed tick (stop marker: play-time, last known wallet vector, wall time). | E1-4 (Aborted runs after the new session started). | DESIGN DECISION (sim-verified) |
| D-SL-8 | "Last known wallet" = value read at the start of the last tick, updated by LSAX's own writes in that tick. Continuation after a quick restart (< 10 s wall) requires the wallet to equal it (or a pending txn's `cash_after`); a different GTA process id forbids continuation. | **Sim-driven.** Continuation was wrongly rejected after a post-commit crash; an in-session load of another branch was confused with continuation. | DESIGN DECISION (sim-verified) |
| D-SL-9 | Commits in the same play-time granule as a save are resolved by the saved wallet: exactly one prefix length must explain it, else ambiguous. Continuation uses the full active path (no play-time cut). | **Sim-driven** (G = 1000 ms case: a pending txn restored the pre-commit wallet value). | DESIGN DECISION (sim-verified) |
| D-SL-10 | Unobserved saves (written while LSAX was down) attach to a per-downtime **ghost timeline** forked at the last known head; it only ever receives the pending txn if evidence proves it applied. The new active timeline forks from the ghost's resolved head. | **Sim-driven.** Attaching them to the growing active timeline made a later load include a transaction committed on another branch. | DESIGN DECISION (sim-verified) |
| D-SL-11 | When exactly one save slot explains an anchoring (not continuation, not ghost), LSAX records that slot's exact (play-time, wallet) — upgrading INFERRED to OBSERVED. | Reduces later ambiguity. | DESIGN DECISION (sim-verified) |
| D-SL-12 | NO_MATCH (loaded world explained by no candidate: brand-new game, pre-LSAX save, foreign/copied save file) → RECONCILE_REQUIRED with the explicit player choice "start a new LSAX campaign for this world". Never auto-attach to an existing campaign. | A new campaign cannot duplicate value (sim reasoning in LSAX-SAVELOAD-FEASIBILITY.md §4.7). | DESIGN DECISION |

## Transactions

| ID | Decision | Rationale / evidence | Status |
|---|---|---|---|
| D-TX-1 | Protocol: in ONE game tick: synchronous durable `PREPARE` (txn row + reservation + expected wallet before/after + play-time) → re-read wallet, verify == `cash_before` → apply ALL money-coupled game-side effects → synchronous durable `COMMIT` (commit row + projection). A rolled-forward commit is stamped with `p_prepare` (its effects existed from that tick). World actions that cannot complete in one tick (handover scenes, spawns) are separate bounded steps before (precondition) or after (delivery) the atomic core. | E1-8 / A-SL-4: a save snapshot cannot interleave inside one tick. **Sim-driven** stamp fix (rolled-forward commit stamped with recovery play-time excluded it from an earlier save). Cost: 2 fsync'd commits per transaction tick (budget in LSAX-PERFORMANCE-BUDGET.md, measured by P-DB-01). | DESIGN DECISION (sim-verified) |
| D-TX-2 | Recovery of a PREPARED txn is decided only by evidence: same anchor position AND play-time ≥ p_prepare AND wallet == `cash_after` (≠ `cash_before`) → roll forward; wallet == `cash_before` or different position → abort; anything else → RECONCILE_REQUIRED. Money-neutral transactions need another verifiable discriminator or they resolve to RECONCILE_REQUIRED. | Never guess. | DESIGN DECISION (sim-verified) |
| D-TX-3 | Idempotency scope = the active timeline path. A key orphaned by a rewind may be committed again (e.g. the same offer accepted again after loading an earlier save). | The orphaned commit's effects do not exist in the loaded world. | DESIGN DECISION |

## Valuation / generation / heat (sim-driven changes recorded here, full rules in the model docs)
